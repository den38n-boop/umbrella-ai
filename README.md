# Umbrella · Сообщения

Самостоятельная фанатская mystery/thriller игра по мотивам The Umbrella Academy. Игрок пишет за Алину свободным текстом. Это существующий Express-проект; `agents.json` и `world.json` сохранены.

## Запуск и Render

Node.js 20+. `npm ci`, затем `npm start`. Проверки: `npm run check` и `npm test`.

На Render: Build Command `npm ci`, Start Command `npm start`. Сервис использует назначенный Render `PORT` и прежний домен.

Переменные окружения задаются **только на сервере**:

- `OPENROUTER_API_KEY` — ключ OpenRouter; никогда не помещать в frontend, Git или логи.
- `OPENROUTER_MODEL` — необязательно, по умолчанию `openrouter/free`.
- `SAVE_SECRET` — необязательный стабильный случайный секрет для сохранений. Без него ключ шифрования выводится из `OPENROUTER_API_KEY`. При смене API-ключа без отдельного `SAVE_SECRET` старые сохранения перестанут проверяться.

Если оба секрета отсутствуют, приложение запускается, но сохранения действуют только до перезапуска процесса. `.env.example` служит образцом; сервер читает `process.env` (на Node 20.6+ локально можно запускать `node --env-file=.env server.js`).

`/api/health`: `ai:true` означает, что ключ задан, **а не** что генерация проверена. `durableSave:true` означает наличие стабильного источника ключа шифрования.

## Архитектура и защита

- `server.js`: Express API, серверные сессии, последовательная обработка каждой сессии, ограничение частоты, OpenRouter через OpenAI-совместимый SDK. Таймаут одного вызова 20 секунд, одна повторная попытка при повреждённом JSON; нет немедленных повторов при ошибке провайдера. Ошибка AI возвращает сохранённую переписку и `aiStatus:unavailable`.
- `lib/simulation.js`: state, выбор максимум двух участников, отдельная генерация для каждого NPC, обязательная whitelist-валидация, ограниченные изменения отношений/памяти/действий. `Alina` создаётся исключительно `/api/message`; модель не может создать автора вне своего NPC или изменить чужое сообщение. Выходные `world_changes` игнорируются. Глобальные изменения управляются серверными правилами расследований.
- NPC получает собственную карточку, знания, компактную память, отношения, групповые сообщения и только свой личный чат. Скрытая `WORLD.truth`, чужие секреты и чужая личная переписка вообще не отправляются модели. Пользовательский текст передаётся как данные игрового события, без включения в system prompt. Структурная защита не гарантирует художественную точность каждой реплики: модель по-прежнему может выдумывать факты из общего знания о сериале.
- Улики зависят от тем расследований и действительного участника переписки; после паузы результат сообщается только свидетелем в его личном чате. Нет обязательного порядка или дерева ответов. После нескольких расследований может возникнуть неизвестный контакт `08`; этот канал пока только входящий. Раскрытие Number Eight автоматически не происходит.
- `lib/save.js`: AES-256-GCM, шифрование и проверка подлинности сохранения с привязкой к sessionId. Клиент не может переписать NPC memory/state и выдать это за валидное сохранение. Зашифрованное сохранение и sessionId являются доступом к своей игре; не публикуйте экспорт.
- `public/app.js`: список чатов, личные сообщения, непрочитанные, typing перед отображением входящих, временные метки, редактирование/удаление собственных NPC-сообщений, черновики, localStorage, очередь отправки с requestId, экспорт/импорт сохранения. Отмена/таймаут HTTP не меняет исходный пользовательский текст. Повтор запроса с тем же requestId в текущем состоянии не создаёт дубликат.
- `public/style.css`: мобильная навигация, safe area, `100dvh` и visualViewport для изменения высоты при клавиатуре. Manifest, PNG-иконки и service worker дают установку и offline-оболочку. API никогда не кэшируется service worker.

## API

POST JSON; `sessionId` и `requestId` — случайные UUID клиента. Ответ содержит `sessionId`, всю удерживаемую переписку, `contacts`, `statuses`, зашифрованный `save`, `aiStatus`.

- `/api/start`: `{sessionId, save?}` — идемпотентное открытие/восстановление. Новая игра требует нового sessionId. Начальная переписка Five создаётся сервером без вызова AI.
- `/api/message`: `{sessionId, save?, requestId, channel, text}` — `group` или имя известного NPC, до 3000 символов. Только здесь появляется сообщение `Alina`, текст сохраняется буквально.
- `/api/tick`: `{sessionId, save?}` — события без новой реплики игрока; не чаще одного раза в 90 секунд для сессии.
- `/api/health`: конфигурация без секретов.

HTTP 400 — плохой запрос, 403 — cross-site POST, 409 — сессия занята, 410 — отсутствующая сессия без сохранения, 422 — сохранение не прошло проверку, 429 — слишком частые сообщения. Не доверяем именам автора/каналу/ID/меткам времени из модели; неизвестные поля не применяются.

## Бесплатный режим и реальные ограничения

Render Free засыпает после 15 минут без входящих запросов; его файловая система непостоянна ([документация](https://render.com/docs/free)). Поэтому локальный файл на Render не используется как постоянная база: клиент отправляет аутентифицированный зашифрованный snapshot, когда сервер потерял сессию. Пока серверная сессия существует, она имеет приоритет над клиентским snapshot.

Хранятся последние 600 сообщений, с дополнительным пределом 200 КБ UTF-8 для истории; память NPC — последние 18 значимых наблюдений. Сессии без активности более часа вытесняются; максимум 200 сессий в процессе. localStorage зависит от устройства/браузера. Очистка данных сайта теряет игру, если не скачать экспорт. Облачной синхронизации и пользовательских аккаунтов нет. Это восстановление на одном устройстве, а не постоянная серверная БД; несколько вкладок с несинхронизированными снимками могут восстановить устаревшую версию после перезапуска.

`openrouter/free` имеет квоты и возможные ошибки отдельных моделей ([OpenRouter limits](https://openrouter.ai/docs/api_reference/limits)). Вызовы AI идут для пользовательских сообщений и открытого активного приложения; тики при скрытой странице/отсутствии сети пропускаются. Один ход с двумя NPC требует двух запросов, повреждённый JSON может потребовать ещё одну попытку на NPC. Платные модели автоматически не подключаются.

При закрытом приложении симуляция не работает и фоновые push-уведомления не доставляются. Разрешённые локальные уведомления возможны только пока клиент выполняется. Физический iPhone/Safari нужно проверить отдельно: эмуляция viewport не подтверждает поведение настоящей клавиатуры и установку PWA на iOS.

## Доставка изменений

Изменения в ветке/PR не обновляют рабочий Render автоматически до их слияния в подключённую ветку деплоя. После слияния проверить health, свободный ответ NPC, reload и восстановление после перезапуска. При ошибке сохранить snapshot и откатить коммит. На первом обновлении старая версия не имела сохранённых историй: старые серверные сессии не переносятся.
